## Current loading behavior

Shared portal record loading uses deterministic primary-key pages and exact counts, including composite service-preference keys. Smaller server response caps are followed until all counted rows load. Errors, changed counts, duplicate rows, malformed responses or access loss reject the load; no partial portfolio is reported as complete. Retrieval stops explicitly above 50,000 rows per table to bound browser memory. REST pages are not an atomic snapshot: equal-count changes between pages cannot all be detected. This is a safe improvement over silent truncation, not a claim of serializable browsing. Domain-specific histories and feed workers have their own loaders and were not all rewritten here.
